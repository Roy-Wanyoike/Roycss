     1→# RoyCSS — Official VS Code Extension Architecture
     2→
     3→> **Mission:** Make RoyCSS the most productive CSS-effects library to author inside VS Code. The extension brings the 700+ effect registry, design tokens, OKLCH palette, accessibility hints, performance warnings, and AI-assisted suggestions directly into the editor — so developers never need to leave their file to discover, preview, lint, or migrate RoyCSS.
     4→
     5→The extension is published as **`roycss.roycss-vscode`** on the VS Code Marketplace and Open VSX. It is built on the **Language Server Protocol (LSP)** so it also works in VSCodium, Cursor, Windsurf, GitHub Codespaces, and (with adapter shims) Neovim and JetBrains via LSP clients.

    79→### 1.2 Design Principles
    80→
    81→1. **LSP-first.** Every language feature is implemented in the language server; the extension host is a thin shell. This guarantees portability to other LSP clients.
    82→2. **Static-data where possible.** Class metadata is bundled at build time; no runtime fetches for known data.
    83→3. **Zero-config by default, full-config when needed.** Install and it works. Power users can override every behavior.
    84→4. **Performance over completeness.** A 50ms hover is more valuable than a 500ms hover with extra info.
    85→5. **Diagnostics are suggestions, not errors.** RoyCSS classes are CSS — we never block compilation. All diagnostics are warnings or hints.
    86→6. **Offline-first.** The extension works fully offline; AI features degrade gracefully.

   176→### 1.5 Why a Separate Language Server Package?
   177→
   178→- **Reuse.** The same server powers the Neovim and JetBrains clients (via community LSP wrappers).
   179→- **Testability.** The server is a pure Node module — we can test providers without spinning up VS Code.
   180→- **Bundle size.** The extension package stays lean; the server ships only the runtime needed.
   181→- **Independent versioning.** The server can release patch versions faster than the extension's marketplace review allows.

   185→## 2. Extension API
   186→
   187→### 2.1 Public VS Code API Surface
   188→
   189→The extension exposes a small, stable API for other extensions (e.g., a future "RoyCSS for Tailwind IntelliSense bridge"):
   190→
   191→```typescript
   192→// Activated via: const roycss = vscode.extensions.getExtension('roycss.roycss-vscode')?.exports;
   193→
   194→export interface RoyCssExtensionApi {
   195→  /** The full class registry (700+ entries). */
   196→  readonly classes: ReadonlyArray<RoyCssClassEntry>;
   197→
   198→  /** Look up a class by its exact name (e.g. "roycss-pulse-glow"). */
   199→  getClass(name: string): RoyCssClassEntry | undefined;
   200→
   201→  /** Fuzzy search across class names, descriptions, and tags. */
   202→  search(query: string, options?: SearchOptions): RoyCssClassEntry[];
   203→
   204→  /** The design-token registry (colors, spacing, motion, etc.). */
   205→  readonly tokens: ReadonlyArray<RoyCssTokenEntry>;
   206→
   207→  /** Returns the migration target for a foreign class name, if any. */
   208→  getMigrationTarget(foreignClass: string): RoyCssMigrationTarget | undefined;
   209→
   210→  /** Subscribe to registry updates (after a version bump / data refresh). */
   211→  onDidUpdateRegistry(listener: () => void): vscode.Disposable;
   212→}
   213→```

   216→
   217→| Module | Owns | Does Not Own |

   230→## 3. Language Server Protocol
   231→
   232→### 3.1 LSP Capabilities Advertised
   233→
   234→The server declares these capabilities in its `InitializeResult`:
   235→
   236→| Capability | Method | Purpose |
   237→|-----------|--------|---------|
   238→| Completion | `textDocument/completion` | Autocomplete class names |
   239→| Hover | `textDocument/hover` | Preview + documentation tooltips |
   240→| Signature Help | `textDocument/signatureHelp` | (Reserved for token functions) |
   241→| Definition | `textDocument/definition` | Jump to effect source |
   242→| Document Link | `textDocument/documentLink` | Click class → open docs URL |
   243→| Semantic Tokens | `textDocument/semanticTokens` | Colorize RoyCSS classes |
   244→| Diagnostics | `textDocument/publishDiagnostics` | Lint + a11y + perf warnings |
   245→| Code Actions | `textDocument/codeAction` | Sort, migrate, fix conflicts |
   246→| Code Lens | `textDocument/codeLens` | "Preview in docs" lens above class |
   247→| Document Highlight | `textDocument/documentHighlight` | Highlight all usages of a class |
   248→| Rename | `textDocument/rename` | Rename a class across the project |
   249→| Inlay Hints | `textDocument/inlayHint` | Render-cost hint next to class |
   250→
   251→### 3.2 Server Lifecycle
   252→
   253→```typescript
   254→// roycss-lsp/src/server.ts (simplified)
   255→import { createConnection, TextDocuments, InitializeResult } from "vscode-languageserver/node";
   256→import { RoyCssRegistry } from "./registry";
   257→import { CompletionProvider } from "./providers/completion";
   258→import { HoverProvider } from "./providers/hover";
   259→import { DiagnosticEngine } from "./providers/diagnostic";
   260→// ... other providers
   261→
   262→const connection = createConnection();
   263→const documents = new TextDocuments();
   264→documents.listen(connection);
   265→
   266→const registry = new RoyCssRegistry(/* hydrated from data/ JSON */);
   267→const completion = new CompletionProvider(registry);
   268→const hover = new HoverProvider(registry);
   269→const diagnostics = new DiagnosticEngine(registry);
   270→
   271→connection.onInitialize((params): InitializeResult => {
   272→  const opts = params.initializationOptions ?? {};
   273→  registry.configure(opts);
   274→  return {
   275→    capabilities: {
   276→      completionProvider: { resolveProvider: true, triggerCharacters: ["\"", "'", " ", "."] },
   277→      hoverProvider: true,
   278→      definitionProvider: true,
   279→      documentLinkProvider: { resolveProvider: false },
   280→      semanticTokensProvider: { legend: { tokenTypes: ["roycss"], tokenModifiers: ["valid", "invalid", "deprecated"] }, full: true },
   281→      codeActionProvider: { codeActionKinds: ["quickfix", "refactor"] },
   282→      codeLensProvider: { resolveProvider: false },
   283→      documentHighlightProvider: true,
   284→      renameProvider: { prepareProvider: true },
   285→      inlayHintProvider: { resolveProvider: false },
   286→      diagnosticProvider: { interFileDependencies: true, workspaceDiagnostics: false },
   287→      textDocumentSync: 1,
   288→    },
   289→  };
   290→});
   291→
   292→documents.onDidChangeContent((e) => diagnostics.validateDocument(e.document));
   293→documents.onDidOpen((e) => diagnostics.validateDocument(e.document));
   294→connection.onCompletion((p) => completion.provide(p));
   295→connection.onHover((p) => hover.provide(p));
   296→// ... other handlers
   297→
   298→connection.listen();
   299→```
   300→
   301→### 3.3 Class Attribute Parser
   302→
   303→RoyCSS class names appear inside `class="..."`, `className="..."`, `class:roycss-foo` (Svelte), `:class="{ 'roycss-foo': cond }"` (Vue), and Tailwind-style template strings. The parser is a single shared module:
   304→
   305→```typescript
   306→// roycss-lsp/src/parser/class-attribute.ts
   307→export interface ClassSpan {
   308→  /** Absolute offset of the class name in the document. */
   309→  start: number;
   310→  end: number;
   311→  /** The class name, without quotes. */
   312→  name: string;
   313→  /** Which class-attribute syntax it came from. */
   314→  syntax: "html" | "jsx" | "svelte" | "vue" | "astro" | "tailwind-template";
   315→}
   316→
   317→export function findClassSpans(
   318→  document: TextDocument,
   319→  position?: Position,
   320→): ClassSpan[];
   321→```
   322→
   323→It uses a fast regex pre-pass and a small state machine to disambiguate quotes/comments. This single parser feeds completion, hover, diagnostics, semantic tokens, and code actions — no duplicate logic.
   324→
   325→### 3.4 Performance Targets
   326→
   327→| Operation | Budget | Strategy |
   328→|-----------|--------|----------|
   329→| Document open (full parse + diagnostics) | ≤ 80ms | Tree-sitter-style incremental scan |
   330→| Keystroke → completion list | ≤ 30ms p95 | In-memory prefix trie |
   331→| Hover | ≤ 50ms p95 | Pre-rendered markdown cache |
   332→| Diagnostics on save (whole project) | ≤ 400ms | Parallel rule execution, memoized |
   333→| Rename across project | ≤ 1s | Project-wide ripgrep |

   337→## 4. Commands
   338→
   339→The extension contributes these commands to the Command Palette (`Cmd+Shift+P`):
   340→
   341→| Command ID | Title | Default Keybinding |
   342→|-----------|-------|-------------------|
   343→| `roycss.sortClasses` | RoyCSS: Sort classes in this element | `Ctrl+Shift+S` (editor) |
   344→| `roycss.migrate` | RoyCSS: Migrate foreign classes… | — |
   345→| `roycss.insertSnippet` | RoyCSS: Insert snippet… | `Ctrl+Shift+R` |
   346→| `roycss.openInDocs` | RoyCSS: Open class in documentation | `Ctrl+Shift+D` |
   347→| `roycss.previewInWebview` | RoyCSS: Preview effect in side panel | `Ctrl+Shift+P` (editor) |
   348→| `roycss.toggleTheme` | RoyCSS: Toggle preview theme | — |
   349→| `roycss.copyHtml` | RoyCSS: Copy HTML for current class | — |
   350→| `roycss.copyCss` | RoyCSS: Copy CSS for current class | — |
   351→| `roycss.exportCollection` | RoyCSS: Export current file's classes as collection | — |
   352→| `roycss.suggestEffect` | RoyCSS: AI — suggest effect for selection | `Ctrl+Shift+A` |
   353→| `roycss.openExplorer` | RoyCSS: Open Component Explorer | — |
   354→| `roycss.openTokenPanel` | RoyCSS: Open token inspector | — |
   355→| `roycss.showReleaseNotes` | RoyCSS: Show release notes | — (auto on update) |
   356→
   357→### 4.1 Command: Sort Classes (`roycss.sortClasses`)
   358→
   359→Reorders all RoyCSS classes within the current `class=""` attribute using a deterministic order:
   360→
   361→```
   362→1. Layout & structure   (none in RoyCSS, reserved)
   363→2. Backgrounds          (bg-*)
   364→3. Borders              (border-*)
   365→4. Filters              (filter-*)
   366→5. Visual / glass       (glass-*, visual-*)
   367→6. Text                 (text-*)
   368→7. Transform            (transform-*)
   369→8. Animations           (anim-*)
   370→9. Hover                (hover-*)
   371→10. Microinteractions   (micro-*)
   372→11. Cursor / particles  (cursor-*, particle-*)
   373→12. Other / misc        (alphabetical within group)
   374→```
   375→
   376→Non-RoyCSS classes (Tailwind, Bootstrap, custom) are preserved in their original positions and never reordered. The sort runs as a workspace edit so it composes with Format Document.
   377→
   378→### 4.2 Command: Migrate (`roycss.migrate`)
   379→
   380→Opens a Quick Pick:
   381→
   382→```
   383→Migrate from:
   384→  ❯ Animate.css
   385→    Tailwind CSS
   386→    Bootstrap
   387→```
   388→
   389→After selecting a source, the extension scans the workspace for foreign class names (using the `migration-map.json` registry), presents a preview diff, and applies renames as a single workspace edit. Unmapped classes are listed in a "Review needed" output channel.
   390→
   391→### 4.3 Command: AI Suggest (`roycss.suggestEffect`)
   392→
   393→Collects context (current selection, surrounding element, project framework, theme) and asks the RoyCSS AI endpoint for a suggested effect. The response is inserted as an inline suggestion (ghost text) the user can accept with `Tab` or dismiss with `Esc`. See §8.4 for the completion flow.
   394→
   395→### 4.4 Command: Open in Docs (`roycss.openInDocs`)
   396→
   397→If the cursor is on a RoyCSS class name, opens the corresponding `https://roycss.dev/docs/effects/...` page in the user's default browser. If the class is deprecated, the URL pins to the version where it was last valid.

   401→## 5. Snippets
   402→
   403→### 5.1 Native Snippets (`snippets/roycss.json`)
   404→
   405→A curated set of native VS Code snippets (generated from `vscode-support/roycss-snippets.json` plus richer metadata). Each snippet:
   406→
   407→- Has a meaningful prefix (`roycss-pulse-glow`, `roycss-hover-glow-border`, …).
   408→- Inserts a complete HTML scaffold with the class applied and a placeholder for content.
   409→- Has a description that matches the docs site.
   410→- Is scoped to `html, jsx, tsx, vue, svelte, astro` to avoid noise in non-template files.
   411→
   412→Example:
   413→
   414→```json
   415→{
   416→  "Pulse Glow": {
   417→    "prefix": "roycss-pulse-glow",
   418→    "body": [
   419→      "<div class=\"roycss-pulse-glow\">",
   420→      "  ${1:Content}",
   421→      "</div>"
   422→    ],
   423→    "description": "A smooth pulsing glow effect that draws attention to elements. Honors prefers-reduced-motion.",
   424→    "scope": "html,jsx,tsx,vue,svelte,astro"
   425→  }
   426→}
   427→```
   428→
   429→### 5.2 Snippet Generation Command (`roycss.insertSnippet`)
   430→
   431→Beyond native snippets, `roycss.insertSnippet` opens a Quick Pick with **all 700+ effects** filtered by what the user types, plus preview thumbnails (rendered as Markdown images via the docs site's preview API). Selecting one inserts the framework-appropriate scaffold (auto-detected from the current file's language).
   432→
   433→```
   434→┌────────────────────────────────────────────────────────────┐
   435→│  Insert RoyCSS effect                                      │
   436→│                                                            │
   437→│  Type to filter 700+ effects…                              │
   438→│                                                            │
   439→│  ▸ roycss-anim-pulse-glow      · Animations · ▶ thumbnail  │
   440→│    roycss-anim-pulse-soft      · Animations                │
   441→│    roycss-hover-glow-border    · Hover                     │
   442→│    roycss-text-neon-glow       · Text                      │
   443→│    ...                                                     │
   444→└────────────────────────────────────────────────────────────┘
   445→```
   446→
   447→### 5.3 Framework-Aware Body Generation
   448→
   449→The snippet body adapts to the current language:
   450→
   451→| Language | Body Shape |
   452→|----------|-----------|
   453→| HTML / Astro | `<div class="roycss-pulse-glow">$1</div>` |
   454→| JSX / TSX | `<div className="roycss-pulse-glow">$1</div>` |
   455→| Vue | `<div :class="'roycss-pulse-glow'">$1</div>` (or static `class=`) |
   456→| Svelte | `<div class="roycss-pulse-glow">$1</div>` |
   457→| Angular template | `<div class="roycss-pulse-glow">$1</div>` |
   458→
   459→For effects with required child elements (e.g. loaders with `<span>`s), the snippet includes the correct `childCount` of placeholder spans.
   460→
   461→### 5.4 Snippet Variants
   462→
   463→Each snippet also exposes variants via tab-stops. Typing `roycss-pulse-glow` and pressing `Tab` cycles:
   464→
   465→1. Default class
   466→2. `-soft` variant
   467→3. `-strong` variant
   468→4. `-slow` variant
   469→5. Back to default
   470→
   471→This lets developers try intensity/speed variants without retyping.

   475→## 6. Diagnostics
   476→
   477→### 6.1 Diagnostic Severities
   478→
   479→RoyCSS diagnostics use three severities (never `Error`):
   480→
   481→| Severity | Use |
   482→|----------|-----|
   483→| `Warning` | Likely bugs: invalid class, conflicting utilities, perf issue |
   484→| `Information` | Suggestions: dead class, missing aria |
   485→| `Hint` | Style nits: unsorted classes, redundant variant |
   486→
   487→### 6.2 Lint Rules
   488→
   489→#### R1. Invalid Class
   490→
   491→```
   492→⚠  "roycss-pulse-gloww" is not a valid RoyCSS class.
   493→   Did you mean "roycss-pulse-glow"? [Quick Fix]
   494→```
   495→
   496→- Matches `roycss-*` tokens against the registry using Levenshtein distance ≤ 2.
   497→- Quick Fix: replace with the closest match.
   498→- Severity: Warning.
   499→
   500→#### R2. Conflicting Utilities
   501→
   502→```
   503→⚠  "roycss-anim-pulse-glow" and "roycss-anim-shake" both animate the same element.
   504→   Browsers will only honor the last `animation` declaration. [Quick Fix: keep one]
   505→```
   506→
   507→- Detects two animation classes on the same element (CSS `animation` shortens on declaration).
   508→- Also flags two hover effects that both animate `transform`.
   509→- Quick Fix: removes one (user picks).
   510→
   511→#### R3. Deprecated Class
   512→
   513→```
   514→ℹ  "roycss-float" is deprecated since v1.4.0. Use "roycss-anim-float" instead.
   515→   [Quick Fix: rename] [Open migration guide]
   516→```
   517→
   518→- Sourced from `effect-metadata.json`'s `versionDeprecated` + `replacementFor`.
   519→- Quick Fix: rename across the project (LSP rename).
   520→
   521→#### R4. Dead Class Detection
   522→
   523→```
   524→ℹ  "roycss-bounce-in" is defined in your CSS but not used in any template.
   525→   Remove or tree-shake? [Quick Fix: remove from CSS]
   526→```
   527→
   528→- Operates in two modes:
   529→  - **Within-document:** class appears in `class=""` but the CSS file doesn't define it (or vice versa).
   530→  - **Project-wide:** scan on save; report RoyCSS classes referenced in templates that aren't in the imported CSS bundle.
   531→- Powered by a workspace-wide class-usage index (rebuilt on save).
   532→- Severity: Information.
   533→
   534→#### R5. Accessibility Hints
   535→
   536→```
   537→ℹ  "roycss-anim-flash" may be unsafe for photosensitive users (flashes > 3 Hz).
   538→   Consider "roycss-anim-pulse-soft" for a motion-safe alternative.
   539→```
   540→
   541→- Flags effects with `flashSafe: false` in metadata.
   542→- Flags animations on elements with `aria-live="polite"` or `aria-live="assertive"` (motion can distract screen-reader users).
   543→- Flags missing `aria-label` on elements whose only child is a decorative RoyCSS loader.
   544→- Severity: Information; Quick Fix: replace with a motion-safe alternative.
   545→
   546→#### R6. Performance Warnings
   547→
   548→```
   549→⚠  6 elements on this page use "roycss-particle-fireflies" (each runs a 5s animation).
   550→   Consider reducing to ≤ 3, or use a single canvas-based particle effect. [Learn more]
   551→```
   552→
   553→- Counts same-class instances per file; warns when count exceeds `effect.metadata.recommendedMaxInstances`.
   554→- Flags combinations known to thrash the compositor (e.g., 4+ simultaneous `filter-*` effects with `backdrop-filter`).
   555→- Flags `anim-*` classes on > 20 elements (suggests `prefers-reduced-motion` guard).
   556→- Severity: Warning.
   557→
   558→#### R7. Theme Compatibility
   559→
   560→```
   561→ℹ  "roycss-text-neon-glow" assumes a dark surface. In light theme the glow may be invisible.
   562→   [Quick Fix: wrap in `.dark:` variant] [Preview in light theme]
   563→```
   564→
   565→- Cross-references effect metadata's `themeAffinity: "dark" | "light" | "both"` with the project's detected theme tokens.
   566→- Quick Fix: wraps the element in a `@media (prefers-color-scheme: dark)` block or adds the framework's dark variant.
   567→
   568→#### R8. Reduced-Motion Guard Missing
   569→
   570→```
   571→ℹ  "roycss-anim-bounce-in" runs unconditionally. Wrap in a `prefers-reduced-motion` guard
   572→   for users who opt out of motion. [Quick Fix: insert guard]
   573→```
   574→
   575→- Only fires when the project hasn't already opted into RoyCSS's global reduced-motion reset (the `@import "roycss";` line includes it by default).
   576→- Quick Fix inserts a media query block.
   577→
   578→### 6.3 Diagnostic Code Actions
   579→
   580→Every diagnostic that can be auto-fixed exposes a Code Action (the lightbulb):
   581→
   582→- Replace invalid class with closest valid match.
   583→- Remove conflicting utility (pick which to keep).
   584→- Rename deprecated class.
   585→- Insert `prefers-reduced-motion` guard.
   586→- Wrap element in dark-mode variant.
   587→- Sort classes in this element.
   588→
   589→Code Actions also surface in the "Source Action" right-click menu for batch application.

   672→## 8. Completion Providers
   673→
   674→### 8.1 Class-Name Completion
   675→
   676→Triggered by:
   677→
   678→- Typing inside `class="`, `className="`, `:class="`, `class:` (Svelte).
   679→- Pressing `Space` after an existing class (to add another).
   680→- Manually via `Ctrl+Space` anywhere a class name is valid.
   681→
   682→The completion list shows **all 700+ classes**, ranked by:
   683→
   684→1. **Prefix match** — classes starting with the typed prefix rank highest.
   685→2. **Fuzzy match** — `plsGlow` matches `roycss-anim-pulse-glow`.
   686→3. **Context relevance** — if the cursor is inside a `<button>`, button-effects (`btn-*`, `hover-*`) rank higher; inside `<input>`, form effects (`form-*`) rank higher.
   687→4. **Project history** — classes already used in this workspace rank higher.
   688→5. **Global popularity** — most-copied effects (per the docs site's telemetry) rank higher when no other signal dominates.
   689→6. **Recency** — newly added effects in the installed RoyCSS version get a small boost.
   690→
   691→### 8.2 Completion Item Shape
   692→
   693→Each completion item includes:
   694→
   695→```typescript
   696→interface RoyCssCompletionItem extends vscode.CompletionItem {
   697→  detail: string;              // "Animations · 0.42 kB"
   698→  documentation: vscode.MarkdownString;  // preview + a11y + variants
   699→  sortText: string;            // padded rank, e.g. "0001"
   700→  filterText: string;          // alias-friendly, e.g. "pulse-glow anim-pulse-glow"
   701→  insertText: string;          // "roycss-anim-pulse-glow"
   702→  kind: vscode.CompletionItemKind.Class;
   703→  tags: vscode.CompletionItemTag[];  // [Deprecated] if applicable
   704→  command?: { command: "roycss.onClassInserted", title: "", arguments: [...] };
   705→}
   706→```
   707→
   708→The `command` field fires a telemetry event (opt-in) and triggers a 100ms delayed preview panel update if the user has the side panel open.
   709→
   710→### 8.3 Sort Order Visualization
   711→
   712→The completion list groups items visually:
   713→
   714→```
   715→┌────────────────────────────────────────────────────────────┐
   716→│  Animations                                                │
   717→│  ─────────                                                 │
   718→│  ▸ roycss-anim-pulse-glow      · 0.42 kB · motion-safe     │
   719→│    roycss-anim-pulse-soft      · 0.38 kB · motion-safe     │
   720→│    roycss-anim-pulse-ring      · 0.51 kB · motion-safe     │
   721→│  Hover                                                     │
   722→│  ─────────                                                 │
   723→│    roycss-hover-glow-border    · 0.27 kB · motion-safe     │
   724→│  Text                                                      │
   725→│  ─────────                                                 │
   726→│    roycss-text-neon-glow       · 0.36 kB · ⚠ contrast      │
   727→└────────────────────────────────────────────────────────────┘
   728→```
   729→
   730→Group headers come from `vscode.CompletionItemKind.Module` separator items; this keeps the list scannable across 700+ entries.
   731→
   732→### 8.4 AI-Assisted Utility Suggestions
   733→
   734→When the user types a class attribute and pauses for > 400ms without selecting, the extension calls the AI suggestion engine with:
   735→
   736→```typescript
   737→interface AiSuggestionContext {
   738→  /** The partial class name typed so far. */
   739→  partial: string;
   740→  /** The element tag being styled. */
   741→  elementTag: string;
   742→  /** Surrounding JSX/HTML context (parent, siblings). */
   743→  elementContext: ElementContext;
   744→  /** The framework detected (react, vue, svelte, html). */
   745→  framework: Framework;
   746→  /** The project's theme tokens (extracted from CSS/SCSS). */
   747→  theme: ThemeSnapshot;
   748→  /** Classes already on this element. */
   749→  existingClasses: string[];
   750→  /** Whether the cursor is in a hover context (inside :hover CSS rule, etc.). */
   751→  isHoverContext: boolean;
   752→}
   753→```
   754→
   755→The AI endpoint returns 1–3 suggested RoyCSS classes with a confidence score and a one-line explanation. These surface as:
   756→
   757→- **Inline ghost-text suggestions** (gray text after the cursor) — accept with `Tab`.
   758→- **Top-of-completion-list items** with an ⚡ icon and "AI" badge.
   759→
   760→If the user has AI suggestions disabled (default off for privacy), the extension falls back to pure registry completion.
   761→
   762→### 8.5 Variant Completion
   763→
   764→After inserting `roycss-anim-pulse-glow`, pressing `-` triggers variant completion:
   765→
   766→```
   767→┌────────────────────────────────────────────────────────────┐
   768→│  roycss-anim-pulse-glow-|                                  │
   769→│                                                            │
   770→│  ▸ -soft      (3.0s, 50% intensity)                        │
   771→│    -strong    (1.2s, 150% intensity)                       │
   772→│    -slow      (4.0s, default intensity)                    │
   773→│    -fast      (0.8s, default intensity)                    │
   774→└────────────────────────────────────────────────────────────┘
   775→```
   776→
   777→This nudges users toward the variant system without requiring them to read the docs.

   873→### 9.2 Workspace vs. User Settings
   874→
   875→- **Telemetry** is always user-scoped (never workspace) so workspaces can't enable it without consent.
   876→- **AI** defaults to off and requires explicit user opt-in (workspace or user scope).
   877→- **Diagnostics rules** are typically workspace-scoped so teams can enforce a shared baseline (committed in `.vscode/settings.json`).
   878→
   879→### 9.3 Configuration Validation
   880→
   881→On activation, the extension validates settings:
   882→
   883→- Unknown rule names → warning notification with a "Reset to defaults" button.
   884→- AI enabled without an endpoint → prompts user to confirm the default endpoint.
   885→- Pinned version that's no longer in the registry → warns and offers to switch to `auto`.

   891→### 10.1 From the Marketplace
   892→
   893→1. Open VS Code.
   894→2. Open Extensions (`Cmd+Shift+X`).
   895→3. Search "RoyCSS".
   896→4. Click Install.

   899→
   900→### 10.2 From Open VSX (VSCodium, Cursor, Gitpod)
   901→
   902→```
   903→Extensions: Search "RoyCSS" → Install
   904→```
   905→
   906→Open VSX releases ship within 24 hours of the Marketplace release.
   907→
   908→### 10.3 From Source (Developers)
   909→
   910→```bash
   911→git clone https://github.com/Roy-Wanyoike/roycss.git
   912→cd roycss
   913→bun install
   914→bun run build:vscode        # builds packages/vscode-roycss + roycss-lsp
   915→code --install-extension packages/vscode-roycss/roycss-vscode-*.vsix
   916→```
   917→
   918→For development with hot reload:
   919→
   920→```bash
   921→bun run dev:vscode          # watches and recompiles
   922→# In VS Code: press F5 → launches an Extension Development Host
   923→```
   924→
   925→### 10.4 Verification
   926→
   927→After install, run the command `RoyCSS: Show release notes`. If the extension is healthy, you'll see:
   928→
   929→- A welcome webview listing the 700+ available classes.
   930→- A status bar item showing `RoyCSS: 700 classes · v1.4.0`.
   931→- Hovering on any `roycss-*` class name in an HTML file shows the rich hover.
   932→
   933→If nothing appears:
   934→
   935→- Check the output channel "RoyCSS Language Server" for errors.
   936→- Run `RoyCSS: Restart language server`.
   937→- File an issue with the output channel contents: `RoyCSS: Report issue`.
   938→
   939→### 10.5 Uninstall
   940→
   941→Standard VS Code uninstall. The extension removes its `~/.vscode/extensions/roycss.roycss-vscode-*` directory. No persistent state is left in user settings unless the user added settings manually.
   942→
   943→### 10.6 Enterprise / Air-Gapped Install
   944→
   945→The `.vsix` is self-contained — all data (`roycss-classes.json`, snippets, tokens, metadata) is bundled. The only external calls are:
   946→
   947→- The docs site ("Open in docs" command) — optional.
   948→- The AI endpoint — only if `roycss.ai.enabled` is true.
   949→
   950→For air-gapped environments, set `roycss.ai.enabled: false` and the extension works fully offline.

   978→- **Q4:** Migration + Webviews + Polish (P8–P10) — "RoyCSS replaces three other extensions"

   980→### 11.3 Non-Goals (Explicitly Out of Scope)
   981→
   982→- We do not bundle a CSS formatter (use Prettier).
   983→- We do not bundle a Tailwind compatibility shim (use the Tailwind extension; RoyCSS coexists).
   984→- We do not bundle a linter for non-RoyCSS CSS (use Stylelint).
   985→- We do not ship a GUI theme builder (that lives on the docs site).
   986→- We do not support VS Code versions older than the latest 6 months (security + LSP API stability).

  1000→### 11.5 Risks & Mitigations
  1001→
  1002→| Risk | Likelihood | Mitigation |
  1003→|------|-----------|------------|
  1004→| 700-class completion list overwhelms users | High | Group headers, context ranking, variant narrowing |
  1005→| LSP server memory grows with project size | Medium | Class-usage index is LRU-capped at 50MB; rebuild on save |
  1006→| AI endpoint latency / downtime | Medium | Ghost-text suggestions are debounced 400ms; on failure, fall back silently to registry completion |
  1007→| VS Code API breaking changes | Low | Pin `engines.vscode` to a 6-month floor; CI tests against Insiders weekly |
  1008→| OKLCH swatch rendering in non-Chromium editors | Low | sRGB fallback with a clear "RoyCSS ships OKLCH" note |
  1009→| Migration false positives (e.g., user really did mean a Bootstrap class) | Medium | Migration command always shows a diff preview; never auto-applies on save |

  1013→## Appendix A: Data Pipeline (build-time)
  1014→
  1015→```
  1016→src/lib/effects-batch-*.ts    (700+ CSSEffect objects)
  1017→              │
  1018→              ▼
  1019→shared/src/build-data.ts      (pure builder)
  1020→              │
  1021→              ├─► roycss-classes.json    (just the class names, for completion)
  1022→              ├─► roycss-snippets.json   (VS Code snippets + framework bodies)
  1023→              ├─► effect-metadata.json   (a11y, perf, variants, versionAdded)
  1024→              ├─► design-tokens.json     (OKLCH palette, spacing, motion)
  1025→              └─► migration-map.json     (foreign-class → roycss-class)
  1026→              │
  1027→              ▼
  1028→copied into packages/vscode-roycss/data/ and packages/roycss-lsp/data/
  1029→              │
  1030→              ▼
  1031→bundled at build time; no runtime fetch
  1032→```
  1033→
  1034→This pipeline runs on every RoyCSS release. The extension's data files are versioned alongside the RoyCSS package — installing RoyCSS v1.4.0 in your project automatically loads v1.4.0 metadata into the extension (when `roycss.version: "auto"`).

  1036→## Appendix B: Testing Strategy
  1037→
  1038→- **Unit tests (Vitest)** — parser, completion ranking, diagnostic rules, snippet body generation.
  1039→- **Integration tests** — LSP server against fixture workspaces; assert published diagnostics, completion items, hover contents.
  1040→- **End-to-end tests (vscode-test)** — drive VS Code via the extension test harness; assert command outcomes, webview state.
  1041→- **Snapshot tests** — hover Markdown, completion item JSON, to catch unintended changes.
  1042→- **Performance tests** — 10k-line fixture file; assert diagnostic pass < 400ms p95.
  1043→- **Accessibility tests** — webviews pass axe-core in headless Chromium.
  1044→
  1045→All tests run in CI on every PR; merges to `main` require green tests + a successful `.vsix` build.
  1046→
  1047→## Appendix C: Release Process
  1048→
  1049→1. Bump `package.json` version in `packages/vscode-roycss` and `packages/roycss-lsp`.
  1050→2. Update `CHANGELOG.md` with conventional-commit-derived entries.
  1051→3. CI builds the `.vsix`, runs all tests, runs Lighthouse on the bundled webviews.
  1052→4. Tag the release; CI publishes to VS Code Marketplace and Open VSX in parallel.
  1053→5. The docs site's "Editor Setup" page auto-updates to the new version (sourced from the Marketplace API).
  1054→6. The "Show release notes" command fetches the changelog and renders it in a webview on next activation.
