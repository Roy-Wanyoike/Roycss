# RoyCSS VSCode Extension — Threat Model

> Status: **Accepted** · Version: 1.0.0 · Last updated: 2026-07-31
> Scope: `/home/z/my-project/vscode-extension/` and the installable `.vsix`
> Methodology: STRIDE (Microsoft), adapted for a static-data VSCode extension

---

## 1. System under analysis

The RoyCSS VSCode extension is a **static, hermetic, zero-network** extension
that bundles 1,569 CSS effects and provides completion, hover, snippets,
diagnostics, and two commands. The runtime surface area is:

1. `extension.js` (entry point, ~700 lines of plain CommonJS Node.js).
2. `class-data.json` (600 KB of catalog metadata + CSS source per effect).
3. `snippets.json` (210 KB of IntelliSense snippet definitions).
4. `package.json` (manifest — no `scripts` that run on install, no
   `activationEvents` beyond `onLanguage` / `onCommand`).

The extension runs inside the VSCode extension host process and has access
to the workspace filesystem and the user's clipboard. It makes **zero
network calls** and **zero shell exec calls**.

### 1.1 Trust boundaries

```text
┌──────────────────────────────────────────────────────────────┐
│  VSCode Marketplace (untrusted publisher of .vsix)           │
│                       │                                       │
│                       │ .vsix download + signature verify     │
│                       ▼                                       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  VSCode Extension Host (trusted process)               │  │
│  │     └─ RoyCSS extension.js (this scope)                │  │
│  │           ├─ class-data.json (read-only)               │  │
│  │           ├─ snippets.json (read-only)                 │  │
│  │           └─ workspace files (read for diagnostics)    │  │
│  └────────────────────────────────────────────────────────┘  │
│                       │                                       │
│                       │ editor.edit / clipboard.writeText     │
│                       ▼                                       │
│  User workspace + clipboard (trusted, but writable by user)  │
└──────────────────────────────────────────────────────────────┘
```

The three trust boundaries are:
- **T1 — Marketplace → VSCode.** The `.vsix` is downloaded from the marketplace.
  VSCode verifies the signature before installation.
- **T2 — VSCode → extension.js.** The extension host loads `extension.js`.
  Any code in this file runs with the user's permissions.
- **T3 — extension.js → workspace/clipboard.** The extension reads workspace
  files (for diagnostics) and writes to the active editor / clipboard (for
  command insertions).

## 2. STRIDE analysis

### 2.1 Spoofing

| Threat                                        | Risk | Mitigation                                                                                  |
| --------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Malicious `.vsix` impersonates the extension  | Med  | Marketplace requires publisher verification; `publisher: "roycss"` is reserved. The `LICENSE` and `repository.url` fields in `package.json` allow users to verify provenance. |
| Extension host loads a tampered `extension.js` | Low  | The `.vsix` is a signed zip; VSCode refuses to load unpacked extensions from `~/.vscode/extensions` if the manifest signature is broken. |

### 2.2 Tampering

| Threat                                              | Risk | Mitigation                                                                                  |
| --------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Attacker modifies `class-data.json` post-install    | Low  | The file is inside the read-only extension directory (`~/.vscode/extensions/roycss.roycss-1.0.0/`). VSCode marks the directory read-only on install. |
| Attacker submits a PR with a malicious effect CSS    | Med  | The build script (`build.sh`) runs from `dist/effects.json` which is generated by `src/lib/roycss-effects.ts`. The `security/css-exfiltration-check.ts` script audits all CSS for `url()`, `@import`, and `content:` exfiltration vectors — run in CI before any release. |
| Attacker adds a `postinstall` script to `package.json` | High | The extension `package.json` has **no `scripts.postinstall`** field. The `vscode:prepublish` script runs only at packaging time on the publisher's machine, not at install time on the user's machine. `vsce package` refuses to include `postinstall` scripts without `--skip-license` and explicit `trustedDependencies` listing. |

### 2.3 Repudiation

| Threat                                              | Risk | Mitigation                                                                                  |
| --------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Extension performs an action the user didn't request | Low  | Every state-mutating action (editor edit, clipboard write) is a direct consequence of a user-invoked command or a user-accepted completion item. No background timers, no watchers that mutate state. The output channel logs every command invocation. |

### 2.4 Information disclosure

| Threat                                              | Risk | Mitigation                                                                                  |
| --------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Extension leaks workspace contents to the network    | N/A  | Zero network calls (verified by `grep -r 'http\|fetch\|request' extension.js` — returns nothing). |
| Extension leaks workspace contents to the clipboard  | Low  | The only `clipboard.writeText` calls are user-invoked (command palette → browse → copy). The clipboard contents are always the user-selected `roycss-<id>` string, never workspace file contents. |
| Extension logs sensitive data to the output channel  | Low  | The output channel logs only: activation timestamp, effect count, command invocations (with the chosen class id). No file paths, no file contents, no user info. |
| Hover popup exfiltrates CSS via `url()` in `content:` | Low  | `class-data.json` is generated from `dist/effects.json` which is audited by `security/css-exfiltration-check.ts`. The hover popup uses `MarkdownString` with `isTrusted: false` (the default), so any `command:` / `vscode-resource:` URIs in the CSS source are stripped by VSCode. |

### 2.5 Denial of service

| Threat                                              | Risk | Mitigation                                                                                  |
| --------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Malicious workspace file with millions of `roycss-*` tokens causes CPU spin | Low  | Diagnostics scan is debounced 300 ms and capped at files ≤ 200 KB. Larger files are skipped (logged to output channel). |
| 1,569-item completion list freezes IntelliSense       | Low  | `roycss.maxCompletionItems` (default 1,569, min 50) lets users cap the list. The completion provider pre-builds items at activation; per-call cost is a substring filter, not item construction. |
| `class-data.json` is malformed → activate() throws    | Low  | `activate()` wraps `JSON.parse` in try/catch; on failure, logs to output channel and degrades gracefully (providers return empty results). The extension does not crash the extension host. |
| Hover on a `roycss-*` token with 50 KB of CSS freezes the popup | Low  | The hover provider truncates CSS preview to 1,500 chars. The full CSS is available in the source-of-truth file `dist/roycss.css` if the user wants it. |

### 2.6 Elevation of privilege

| Threat                                              | Risk | Mitigation                                                                                  |
| --------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------- |
| Extension executes shell commands                    | N/A  | `extension.js` calls **zero** `child_process.exec` / `execSync` / `spawn` APIs. Verified by `grep -r 'child_process\|exec\|spawn' extension.js` — returns nothing. |
| Extension writes files outside the workspace          | Low  | The only `fs` writes are to the extension's own `globalStoragePath` (provided by VSCode) for the recently-used cache. No writes to arbitrary paths. |
| Extension registers a `taskProvider` that runs shell  | N/A  | The manifest declares no `taskProviders`, no `debuggers`, no `terminal.providers`. The extension cannot run arbitrary commands. |

## 3. Supply chain

### 3.1 Dependencies

The extension's `package.json` declares **zero runtime dependencies** and
**zero devDependencies** (we use plain Node.js + `vsce` from `npx` at build
time, not installed locally). This eliminates the entire npm supply-chain
attack surface for the installed extension.

```jsonc
// package.json
"dependencies": {},
"devDependencies": {},
"trustedDependencies": []
```

### 3.2 Build-time tooling

`build.sh` invokes `npx @vscode/vsce@latest package`. This downloads
`@vscode/vsce` on-demand from the npm registry at build time only (not at
install time on the user's machine). The publisher is responsible for
verifying the `@vscode/vsce` package signature (Microsoft's official
publisher account).

### 3.3 Data integrity

`class-data.json` and `snippets.json` are generated by a Node script from
`dist/effects.json`. The generator script is checked into the repo and runs
in CI. The `security/sbom.ts` script inventories all bundled files; the
`security/css-exfiltration-check.ts` script audits every CSS string in
`class-data.json` for exfiltration vectors. Both run before any release.

### 3.4 .vsix signature

`vsce package` produces an unsigned `.vsix`. For the marketplace release,
the publisher must run `vsce publish` which signs the package with the
publisher's Personal Access Token. The signature is verified by VSCode at
install time. For local development installs (`code --install-extension
roycss-vscode-1.0.0.vsix`), VSCode warns that the extension is unsigned;
users must click "Install Anyway" — this is the standard dev-install
workflow.

## 4. Malicious snippet threat

### 4.1 Attack vector

A snippet's `body` is inserted verbatim into the user's editor. If a snippet
body contained executable code (e.g. a `<script>` tag in HTML, or a
template-literal escape in JS), the snippet would not execute at insert
time — but the user might later run / render the file.

### 4.2 Mitigation

- **Snippet body format.** Every snippet body is exactly three lines:

  ```html
  <div class="roycss-<id>">
    Content
  </div>
  ```

  No `<script>`, no `on*=` event handlers, no `javascript:` URIs, no template
  literals. The `Content` placeholder is a literal string.

- **Generator verification.** The build script (`build-data.js`) asserts
  every snippet body matches the regex
  `^<div class="roycss-[\w-]+">\n  Content\n</div>$`. Any deviation fails
  the build.

- **Source of truth.** The effect `id` is generated from `effects.json`
  which is itself generated from TypeScript source files that go through
  code review. An attacker would need to land a PR adding an effect with a
  malicious `id` (e.g. `id: "foo"><script>alert(1)</script><div class="x"`),
  which would be caught by:
  - The `id` regex validation in `src/lib/roycss-types.ts` (`^[\w-]+$`).
  - The generator's assertion above.
  - The `security/xss-scan.ts` script that flags `<script>` in any
    project string.

### 4.3 Residual risk

**Low.** The only way to inject a malicious snippet is to compromise the
reviewer who approves the PR. The `security/` suite catches automated
attempts; social-engineering attacks on reviewers are out of scope.

## 5. Data integrity

### 5.1 `class-data.json`

- **Source.** `dist/effects.json` (547 KB, 1,569 effects).
- **Generator.** `build-data.js` (Node, ~80 lines).
- **Schema.** Each entry: `{ id, className, name, category, description, tags[], previewType, cssCode }`.
- **Validation.** The generator asserts:
  - `id` matches `^[\w-]+$`.
  - `className` matches `^roycss-[\w-]+$`.
  - `name`, `category`, `description` are non-empty strings.
  - `tags` is a non-empty array of strings.
  - `cssCode` is a non-empty string (may be omitted only if the effect is
    a base/utility class without its own CSS — there are none in the catalog).
  - No duplicate `id` or `className`.
- **Audit.** `security/css-exfiltration-check.ts` audits every `cssCode`
  string for `url()`, `@import`, and `content:` exfiltration vectors.

### 5.2 `snippets.json`

- **Source.** Same `dist/effects.json`.
- **Generator.** Same `build-data.js`.
- **Schema.** `{ "<effectName>": { prefix, body[], description, scope } }`.
- **Validation.** The generator asserts every snippet matches the format
  described in §4.2.

### 5.3 Tamper detection at runtime

At activation, `extension.js` asserts:
- `class-data.json` parsed successfully.
- `class-data.length >= 1500` (defensive lower bound; current catalog is
  1,569). If below, logs a warning but continues — the extension still
  works, just with a smaller catalog.
- The first effect's `className` starts with `roycss-`. If not, refuses
  to activate (the data file is corrupt or tampered).

## 6. Cumulative risk

| Threat category         | Count | Critical | High | Medium | Low | N/A |
| ----------------------- | ----- | -------- | ---- | ------ | --- | --- |
| Spoofing                | 2     | 0        | 0    | 1      | 1   | 0   |
| Tampering               | 3     | 0        | 1    | 1      | 1   | 0   |
| Repudiation             | 1     | 0        | 0    | 0      | 1   | 0   |
| Information disclosure  | 4     | 0        | 0    | 0      | 3   | 1   |
| Denial of service       | 4     | 0        | 0    | 0      | 4   | 0   |
| Elevation of privilege  | 3     | 0        | 0    | 0      | 1   | 2   |
| **Total**               | **17**| **0**    | **1**| **3**  | **11**| **3**|

The single High risk (T2 — `postinstall` script injection) is mitigated by
the manifest having **no `scripts.postinstall`** and `vsce package`
rejecting any attempt to add one without explicit `trustedDependencies`
listing (which our manifest leaves empty).

The three Medium risks are mitigated by:
- T1 (impersonation): publisher verification + reserved `publisher: "roycss"`.
- T2 (PR with malicious CSS): `security/css-exfiltration-check.ts` in CI.
- (None other rated Medium.)

### 6.1 Residual risk

**Low.** The extension's attack surface is minimal:
- Zero network calls.
- Zero shell exec.
- Zero runtime dependencies.
- Zero `postinstall` scripts.
- All data files are static JSON validated at build and runtime.
- All snippet bodies match a strict 3-line HTML wrapper format.

The primary residual risk is **social engineering of a reviewer** to land a
malicious PR. This is addressed by the standard PR review process + the
`security/` audit suite; further mitigation is out of scope for this
extension.
