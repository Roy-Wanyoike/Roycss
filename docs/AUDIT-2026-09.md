## 1. Executive summary

**What RoyCSS is.** RoyCSS is an **AI-native frontend engineering platform** built around a
single technical bet: a very large, high-quality, **zero-JavaScript-runtime catalog of CSS
effects**, wrapped in developer tooling (API, CLI, MCP server, VS Code extension, docs site)
that is designed from day one to be usable by **both humans and LLMs**. It is one repo with
five deployable surfaces: a Next.js frontend/marketing site, an Express+Prisma backend
(`backend-node/`, the running source of truth), a Go modular monolith (`backend-go/`, the
production target with an honest 501-failover design), a Socket.io live service, and an npm
package (`roycss`) shipped from `dist/`. [code: `README.md`, `render.yaml`, `vercel.json`,
`backend-node/src/server/app.ts`]

**Where it stands today.** The codebase is in the best shape of its life: all of the
production-breaking defects found by the September 2026 audit are **fixed and merged**
(PR #68–#74, #76–#79), the full local verification stack is green (111/111 frontend unit
tests, 30/30 backend integration tests, `tsc --noEmit` 0 errors, `next build` succeeds,
API-docs drift gate in sync), and mutating backend endpoints are now authenticated. The
**live site still serves the pre-fix build** because the deploy path is blocked on owner
account actions — GitHub Actions cannot start runners for this account (billing), deploy
secrets are unset, and `vercel.json` points at a dead backend URL. That is tracked, with a
~15-minute runbook, in issue #75. [gh: #75] [cmd: see Appendix 6.2]

#### 2.4.2 The CI "corruption" that wasn't — a forensic worth reading

Issue #59 was filed as "CI pipeline dead: corrupted trigger `branches: ain]`". The CI
agent (worklog Task 2-e) proved the trigger **was never corrupted** — the string `ain]`
was a display artifact of the inspection tooling, which rewrites `[main]` → `ain]` when
file contents pass through certain shell pipes. Five independent proofs: (1) byte-level
`od -c` dump of the git blob; (2) PyYAML parse + assertion that
`on.push.branches == ["main"]`; (3) GitHub Contents API returning the identical blob SHA
for `ci.yml` on main; (4) 80+ Actions runs since 2026-08-29 — impossible with a broken
branches filter; (5) `git pickaxe -S` showing zero commits ever contained the corrupted
string. The PR then fixed what *was* real (gate alignment, lockfile, documented
dependencies) and documented the artifact.

Why this matters beyond trivia: **the audit itself nearly shipped a wrong root cause.**
The discipline of re-verifying observations with independent instruments (raw bytes, API,
history) before acting is the difference between an engineering culture and a patch
sprinkler — and it's the same culture that fixed the other four failures correctly the
first time.

After the P0 wave, the team shipped the compounding-value work:

## 4. Market-gap analysis (investor-facing)

*This section is industry analysis, not repo fact. Repo-sourced claims carry evidence
pointers; competitor statements are qualitative and conservative.*

### 4.1 The market RoyCSS plays in

Frontend styling assets sit in a peculiar spot in 2026: the base layer (Tailwind) won
utilities, the component layer (shadcn/ui and its ecosystem) won copy-paste components, and
the motion layer is dominated by JS runtimes (GSAP, Motion). The **effects layer** — the
thousand small "make this glow / shimmer / stagger / reveal" decisions that every real
frontend makes daily — is served by a long tail of aging single-purpose libraries
(animate.css, Hover.css, loaders.css), ad-hoc generator sites, and vibes. Meanwhile the buyer
changed: a rapidly growing share of "who writes CSS" is now **an AI coding assistant**, which
needs machine-readable catalogs, deterministic copy targets, and rules files more than it
needs another npm package. RoyCSS's catalog is unusually well-shaped for that buyer.

Three buyer personas frame the revenue logic in Sections 4.5 and 5:

1. **The shipping frontend dev** (today's user): needs "a glass card hover that isn't broken
   on Safari" in 60 seconds — finds it via search/SEO, copies in their framework's format,
   never pays, occasionally sponsors. Volume driver.
2. **The AI-native team** (the wedge): works through assistants; wants verified, accessible,
   deterministic effects their agents can retrieve by intent instead of generating
   hallucinated CSS — pays for hosted API/MCP keys. Margin driver (Thesis A).
3. **The design-platform team** (the expansion): wants token governance, theming, and
   collaboration around a shared effect/design language — pays for Roy Cloud tiers and
   eventually enterprise compliance (VPAT/SLA). LTV driver (PF-019/PF-005).

### 4.2 Positioning against the credible alternatives

| Competitor | What it is | Where it beats RoyCSS | Where RoyCSS can win |
|---|---|---|---|
| **Animate.css** | The classic CSS animation library (~80 keyframe utilities in one stylesheet) | Ubiquity, brand trust, zero-decision simplicity, 10+ years of downloads | Scale (1,959 vs ~80 effects ≈ 20×), categories + tags + search, per-effect pages, generators, multi-format copy, API/CLI/MCP. Animate.css is a file; RoyCSS is a platform around a file |
| **GSAP (Webflow)** | The professional JS animation runtime — timeline, physics, SVG, ScrollTrigger; fully free since the 2025 Webflow move | Capability ceiling (JS timelines do things CSS can't), pro mindshare, ecosystem | **Zero-JS runtime** (no bundle cost, no main-thread jank, works with JS disabled — performance/privacy angle), declarative/declarative-adjacent authoring, and the catalog/search/tooling layer GSAP deliberately isn't. GSAP is a runtime, not a catalog |
| **Motion (motion.dev, ex-Framer Motion / Motion One)** | Modern JS motion library for React/vanilla, hybrid engine, spring physics | First-class React integration, small + fast JS runtime, strong DX | Same zero-JS argument; plus breadth (text/glass/loaders/3D/borders categories vs motion primitives). Motion is "how to animate"; RoyCSS is "what to apply, found in seconds" |
| **Tailwind CSS** | Utility-first framework — the current default for utility composition | Distribution, community, docs quality, ecosystem (plugins, UI kits) | **Complements, not competes**: RoyCSS ships copy-as-Tailwind-utility formats (`copy-formats.ts`, tested). Tailwind composes utilities; it doesn't ship 1,959 vetted effect recipes. Position RoyCSS as the effects layer *for* Tailwind users |
| **shadcn/ui** | Copy-paste component registry (Radix + Tailwind) | Component completeness (buttons, dialogs, tables — real UI, not effects), huge distribution, registry standard | Different layer: shadcn gives you the dialog, RoyCSS gives the dialog its entrance shimmer, glow border, and reduced-motion-safe variant. Already co-installs; a shadcn-registry-style distribution of RoyCSS effects is an obvious convergence play |
| **Framer (builder) / generator sites (animista et al.)** | Visual builders and one-off CSS generators | Polished visual editing, brand | RoyCSS's 68 in-site tools + generators approximate the generator value with a persistent, copyable, versioned catalog behind them |

The honest synthesis: **nobody wins by out-GSAP-ing GSAP or out-Tailwind-ing Tailwind.** The
defensible wedge is being the *effects completeness layer* that is (a) zero-JS, (b)
AI-native, and (c) multi-channel (site/API/npm/CLI/MCP/VS Code).

#### 4.2.1 Per-competitor notes (the honest read)

**Animate.css.** Still the gravitational default for "add a CSS animation class" — roughly
80 utilities, one stylesheet, a decade of trust. It beats RoyCSS on simplicity-of-decision
(and on download inertia). It has no search, no tags, no per-effect pages, no generators, no
API, no MCP, no a11y metadata, and a fraction of the breadth (its catalog is one category —
entrances/exits/attention — vs RoyCSS's 29). The strategic relationship is *absorption*, not
competition: RoyCSS's `copy-formats` already reproduces the "one class, zero config" ergonomics,
and the PF-015 codemod backlog explicitly lists an Animate.css → RoyCSS migration path. A
user who outgrows `animate__fadeIn` needs exactly what RoyCSS sells.

**GSAP (Webflow).** The professional ceiling of web motion: timelines, ScrollTrigger, physics,
SVG morphing, and (since the 2025 Webflow acquisition) fully free including plugins. GSAP
will always do things pure CSS cannot — that's not the contested ground. The contested ground
is the ~80% of effects that *are* pure CSS and where a JS runtime is pure overhead: every
kilobyte of GSAP on a marketing page that only wanted a shimmer is a loss. RoyCSS's pitch to
that user: same visual result, zero runtime, zero main-thread work, works with JS disabled.
(GSAP is also a *runtime decision* — RoyCSS is a *content lookup* — so the strongest real
positioning is "pick per surface, not per project".)

**Motion / Motion One (motion.dev).** The modern successor lineage (Framer Motion → Motion),
excellent React DX, hybrid JS engine, spring physics. Same axis as GSAP: it is "how to
animate", while RoyCSS is "what to apply". Motion's catalog is motion primitives, not 29
categories of finished effects. No catalog search, no effect pages, no copy formats. Where
Motion's team optimizes the engine, RoyCSS's moat is the *indexed content* the engine applies.

**Tailwind CSS.** Won utilities; won distribution; a Tailwind-labs "effects" release is the
most credible competitive threat (R5). But Tailwind's design center is utilities for layout/
spacing/typography — shipping 1,959 curated effect recipes is a different curation business.
RoyCSS's already-tested copy-as-Tailwind formats (`framework-adapters.test.ts`, 12 tests)
make the products composable rather than rivalrous: the honest ask is ecosystem adjacency
(the build-plugin roadmap, PF-016, is where that becomes concrete — a Vite/Next plugin that
tree-shakes RoyCSS CSS is a *Tailwind-shaped* product).

**shadcn/ui.** Won the component layer with copy-paste distribution and is now the registry
standard that AI assistants cite. RoyCSS is deliberately the layer *under* it: shadcn ships
the dialog; RoyCSS ships the dialog's `@starting-style` entrance, glass backdrop, and
reduced-motion variant. The convergence opportunity is distribution: a RoyCSS effects
registry in shadcn's format is low technical risk (both are copy-paste + Tailwind-adjacent)
and would put the catalog where frontend developers already shop.

**Generator sites (animista et al.).** These prove the demand for visual effect generation
but ship no persistence: generate, copy, lose. RoyCSS's 68 in-site tools plus a 1,959-entry
indexed catalog convert that behavior into a *saved, searchable, shareable* workflow — the
per-effect URL (PR #77) is the retention mechanism a generator site structurally lacks.

### 4.3 Where RoyCSS can win — four theses

**Thesis A — AI-native CSS tooling (the strongest wedge).** Every serious CSS library today
was designed for humans reading docs. RoyCSS is the only effect catalog in its size class
that ships an MCP server (13 tools / 5 resources / 3 prompts, `mcp-server/`) **as a
first-class product surface**, plus structured per-effect metadata (tags, categories,
framework usage) that LLMs can retrieve deterministically instead of hallucinating class
names. The planned `roycss.rules.md` + training-pairs distribution (PF-021) extends this to
the "drop a rules file in the repo" lane that Tailwind/shadcn only partially occupy via
community efforts. If AI assistants become the primary CSS author, the library that is
*retrievable* wins — and completeness + structure is exactly what retrieval needs. Evidence
that this is real, not slideware: the MCP server exists and is versioned (v2.0.0), the docs
site has an AI-workflow guide, and 5 backend modules are LLM-backed with honest mock
fallbacks.

**Thesis B — zero-JS-runtime effects (performance + privacy).** 1,959 effects are pure CSS:
no runtime kilobytes, no main-thread scheduling, no hydration cost, works with JavaScript
disabled, nothing to CSP-block. Against JS motion runtimes this is a real trade-off axis
(bundle budget, INP on low-end devices, strict privacy contexts). The catalog even encodes
the accessibility half (431 effects with built-in `prefers-reduced-motion` guards — 22%).
This is a *positioning* asset as much as a technical one: "the effects library that ships
zero JavaScript" is a sentence a CTO remembers.

**Thesis C — the completeness moat.** 1,959 effects across 29 categories, test-pinned, with
68 generator tools, multi-format copy, and 1,959 SEO pages, is simply hard to assemble —
competitors would need sustained curation effort to match breadth, and the catalog count is
pinned by CI so it can't silently rot. SEO is the compounding channel: 1,959
long-tail pages ("css glass card hover", "loader dots css") each with live preview and
copyable code is a durable organic-acquisition machine *once deployed* (see risk R3).

**Thesis D — design-token / OKLCH modernity.** 75% of the catalog (1,469 effects) uses OKLCH
color; the design system is token-based with a docs page dedicated to OKLCH. Most legacy
effect libraries are sRGB/hex era. This matters to the buyers who care about theming (the
Roy Cloud thesis, PF-019) and gives the platform a credible "modern CSS by default" story
(scroll-driven animations, `@property`, container queries tooling) that reads as
differentiation to senior engineers evaluating freshness.

### 6.4 Glossary (for non-engineering readers)

| Term | Meaning in this document |
|---|---|
| Effect | One self-contained CSS recipe (e.g. "glass card hover lift") with metadata, preview, and copy formats — 1,959 exist |
| MCP (Model Context Protocol) | The open protocol that lets AI assistants (Claude, Cursor, …) call external tools; RoyCSS ships an MCP server exposing its catalog |
| Zero-JS runtime | Effects are pure CSS — no JavaScript library loads or executes to render them |
| OKLCH | A modern CSS color space with perceptual uniformity; used by 75% of the catalog |
| `prefers-reduced-motion` | The CSS media feature that disables animation for users who opt out — an accessibility requirement |
| Prisma / ORM | The typed database layer; 46 models define the backend's data |
| `requireAuth` / `requireRole` | Backend middleware that rejects unauthenticated writes and enforces org roles (OWNER/ADMIN/MEMBER/VIEWER) |
| Drift gate | A script (`api:check`) that fails when documentation and code disagree |
| PF-### | Item ID in `docs/PENDING-FEATURES.md`, the prioritized backlog (P0 blocker → P3 v2) |
| VPAT | Voluntary Product Accessibility Template — the formal accessibility report enterprise/government buyers require |
| Static prerender / SSG | Pages compiled to plain HTML at build time (fast, cacheable, SEO-friendly) — 2,012 pages build this way |
| ISR | Incremental Static Regeneration — static pages that refresh on a schedule (effect pages: daily) |
